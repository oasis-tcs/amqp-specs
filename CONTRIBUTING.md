## Repository Contributions, Participation, and Public Access

*Who may Contribute?* Contributors to [this repository](https://github.com/oasis-tcs/amqp-specs) are expected to be [Members](https://www.oasis-open.org/policies-guidelines/oasis-defined-terms-2017-05-26#dMember) of the [OASIS Advanced Message Queuing Protocol (AMQP) TC](https://www.oasis-open.org/committees/amqp/) for any
substantive contributions.  Anyone wishing to [participate](https://www.oasis-open.org/org/faq#committee-participation) in the TC's technical activity is invited to [join](https://www.oasis-open.org/committees/join) as a TC Member *Member* in this context means any TC role or office other than OASIS TC Observer, per the [TC Process](https://www.oasis-open.org/policies-guidelines/tc-process#membership). 

*Public comments*. Persons who are not TC members are invited to provide comments on the TC's work by posting to the [AMQP comment list](https://groups.oasis-open.org/communities/community-home?CommunityKey=f83ec4e4-c2ad-4e1f-b9d2-018f5aa7a390). Posting requires a free OASIS account; [sign up here](https://www.oasis-open.org/comment-signup/?tc=amqp). Posting to the comment list is how a commenter accepts the terms of the [OASIS Feedback License](https://www.oasis-open.org/policies-guidelines/ipr#appendixa), which allows the TC to consider the comment. GitHub issues and pull requests are not channels for public comments. Issues opened or commented on by GitHub handles not listed in [`tc/members.txt`](tc/members.txt) or [`tc/staff.txt`](tc/staff.txt) are automatically answered with a redirect to the comment list and labelled `public-comment-redirected`. The workflow does not change whether an issue is open or closed.

*Specification text*. Proposed specification text or mechanisms may be supplied only by TC members, because membership carries the IPR commitments that apply to contributions. A pull request from a person who is not a TC member that proposes specification text cannot be merged as written; please describe the proposal in a post to the comment list instead.

Maintain [`tc/members.txt`](tc/members.txt) with the GitHub handles of TC members and [`tc/staff.txt`](tc/staff.txt) with OASIS staff handles exempt from the automated redirect. Use one handle per line, without the `@` prefix. The staff list does not confer TC membership or permission to contribute specification text. During public reviews, TC members must send review comments to the TC general email list. Do not discuss the substance of a public comment on GitHub or tell commenters to email the list; the Higher Logic community does not accept email from outsiders.

When preparing the public-review resolution log, check issues labelled `public-comment-redirected` against the comment list. A comment posted only on GitHub cannot be included in that log.

Run the issue-policy regression tests with `python -m unittest discover -s tests -p test_issue_policy.py`. The tests require Bash and mock all GitHub API calls.

*Use of Contributions*. As with all OASIS Technical Committee assets - [wikis](https://wiki.oasis-open.org/), [Issues Trackers](https://issues.oasis-open.org/secure/Dashboard.jspa), [email archives](https://lists.oasis-open.org/archives/) - content placed into this GitHub repository is visible and publicly accessible.  Subject to applicable [licensing](https://github.com/oasis-tcs/amqp-specs/blob/master/LICENSE.md) rules, the repository content may be re-used freely, including the creation and publication of derivative works.

*Cloning and forking*. May users clone and fork this repository? Yes. Just as versioned content maintained in any OASIS TC's [SVN/Subversion repository](https://tools.oasis-open.org/version-control/browse/) may be checked out to a remote SVN repository and used by anyone, this GitHub repository may be forked or cloned for use by any party.

Please see the [README](https://github.com/oasis-tcs/amqp-specs/blob/master/README.md) for general description of this repository, and the [LICENSE](https://github.com/oasis-tcs/amqp-specs/blob/master/LICENSE.md) file for licensing.
